# Rut IQ audit — October 9, 2026

## Verdict

Not ready for public signup. The core map, mobile navigation, membership boundaries, and server protections passed the checks below. Email delivery is the first launch blocker. This is a targeted code/configuration and functional audit, not a penetration test or physical-iPhone certification.

Scope: Rut IQ only. No Woods IQ or social-app changes. No paid checkout enabled. No public test sightings created.

Repository main at inspection: 3f52dc008f3e60e1ee35868bee97bd2cfa2557c4.
Live frontend: b2faf59a530a77a33a183e1992ecdb8a386aba9a.
Live deployment: dep-db4g11c9v7es73ah29f0.
Live index.html and app.js were byte-for-byte identical to main; newer commits were documentation, tests, and prepared email templates.

## Findings, in priority order

### 1. Blocker — ordinary hunters cannot rely on the current signup email configuration

Custom SMTP was rolled back after actual Supabase confirmation requests returned SMTP 535 Authentication credentials invalid. The standalone SMTP credential test had passed, but this did not prove the dashboard's saved credential worked.

The fallback is Supabase's built-in email service. Its documentation restricts recipients to project-team addresses; the dashboard rollback dialog specifies two emails per hour. A successful request to the project owner's address therefore does not establish public signup readiness. Branding is currently inactive, and hosted templates were reset by rollback.

Fix: correctly save a dedicated Rut IQ SMTP credential, reapply the prepared templates, then verify an authorized non-team test recipient, provider delivery, and the actual link returning to Home. Preserve email confirmation and keep other apps isolated.

Reference: https://supabase.com/docs/guides/auth/auth-smtp

### 2. High — opening the map during slow geography loading leaves it partially initialized

Reproduced against the live app in an isolated Chrome session by delaying only regions.json for five seconds and immediately selecting Explore.

Result after geography finished: 51 regions loaded, but the map state selector still contained only its placeholder and nameByFips contained zero entries.

Cause: app.js initMapData sets stateBounds and builds its state/FIPS lookups before the independent regions.json promise resolves. Later calls return early once stateBounds exists, so those lookups are not rebuilt.

Fix: await a shared geography-ready promise before map initialization, and only mark initialization complete after all required lookups exist. Recheck a fresh visit on a slow connection.

### 3. Medium — state/county validity is enforced only in the browser

The database checks string lengths but has no canonical state/county reference constraint. A rollback-only test, acting as the authenticated role under a temporary QA identity, successfully inserted Alabama / This County Does Not Exist.

The fixture was forced hidden by the existing QA trigger and rolled back. No fabricated observation was published or retained.

Fix: validate submitted state/county pairs against canonical geography on the backend. Prefer stable FIPS identifiers with matching display names. The existing browser selector is useful but cannot protect direct API submissions.

### 4. Medium — email rate-limit guidance is inaccurate

A mocked hourly email-limit response with error_code over_email_send_rate_limit produced: “Too many sign-in requests. Please wait a minute before trying again.”

The current provider-wide hourly quota may not clear after a minute. The button also becomes immediately available again. Network failures expose “Failed to fetch” rather than useful recovery instructions.

Fix: distinguish hourly provider limits from short resend cooldowns, use safe retry guidance, and provide clear offline/service-unavailable messages. The test intercepted requests locally and sent no email.

### 5. Medium — nationwide date windows use UTC instead of a defined hunting-day timezone

The database timezone is UTC. Aggregates use CURRENT_DATE, while the report form uses the device's local date. Daily report wording says today/yesterday without explaining the difference.

Consequently, evening cutoffs in U.S. timezones can differ from what hunters expect. This is established by code/configuration inspection; a physical-device midnight rollover was not tested.

Fix: define date-window semantics explicitly, then use the same convention throughout filtering and displayed labels. County-local time is a product choice requiring careful handling of counties that span timezones.

### 6. Medium — Pro behavior summary silently stops at 200 recent reports

app.js loadReports requests at most 200 sanitized records, without pagination, and render derives the behavior bars from that list. The county total comes from the full aggregate. A busy county could therefore display partial behavior counts beside a complete report total without a sample label.

This is a code-level finding; the live database currently has no reports, so no real high-volume county was used.

Fix: use complete server aggregates for the chart, or clearly label a capped sample and paginate the report feed.

### 7. Operational — automatic deployment cannot be relied upon

Render reports autoDeploy enabled, but main is newer than the live deployment, and previous pushes required manual deployment. Current frontend bytes match main, so this is not a present frontend mismatch.

Fix: repair/verify the Git integration, then verify that a future intended runtime commit creates a deployment. Continue checking deployment status explicitly in the meantime.

## Checks that passed during this audit

- Live mobile map suite: 320x568, 375x667, 390x844, 430x932, 844x390, and 390x400.
- County taps/actions, filters, layers, live city search, simulated keyboard/search failures, history, navigation, guest Free gates, and disabled checkout.
- Welcome/signup entry points and simulated authenticated Home callback/cross-tab behavior.
- Account-deletion handler tests: sign-in guard, typed confirmation, cancel, request, local cleanup, and failure recovery.
- Server tests: public assets allowed; code, database/test files, directory listing, and traversal paths denied.
- Live security headers present; /server.py, /database/self_service_deletion.sql, and /.git/config returned 404.
- rut_reports and rut_memberships have RLS enabled; ownership policies and public grants inspected.
- Existing transactional membership suite passed: automatic Free membership, role/ownership isolation, self-upgrade denial, protected report status, hidden QA, 7/30-day and Daily Report aggregation, Pro tester access, and expired/past-due entitlement denial.
- Public aggregate definitions exclude hidden QA reports; public detail output omits names, emails, user IDs, and notes.
- Privacy copy discloses external address search and does not promise that search text never leaves the device.
- Pricing remains $7.99/month or $49.99/year; historical intelligence and county alerts are marked planned.

Supabase's security advisor returned one warning: leaked-password protection disabled. The visible app uses passwordless links, so this does not explain the SMTP outage. Review backend password-auth exposure before launch. Remediation: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

## Verification limits and final snapshot

After rollback tests: 1 auth account, 0 confirmed accounts, 1 membership, 0 reports, 0 QA accounts. These are a timestamped snapshot, not permanent counts.

No new real email was requested during this audit. The earlier fallback request returned HTTP 200; inbox receipt and successful fresh signup were not confirmed here.

Physical iPhone signup, submission, map interactions with the real keyboard, and self-service deletion remain unverified by this audit. No current real public report was available for a full visible submission-to-heat-map check. Prior isolated QA report testing is documented separately.

Recommended sequence: fix and verify public email delivery, fix slow map initialization, enforce canonical counties, improve auth recovery, then resolve date/count semantics and run a real-device acceptance pass.
